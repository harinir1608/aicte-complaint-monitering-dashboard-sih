📋 Overview

The AICTE Integrated Complaint Monitoring Dashboard centralises institution-related complaints and regulatory cases across AICTE's Regulation Bureau (RB), Public Grievance Redressal Cell (PGRC), regional offices, and authorised Bureaus/Cells.

Problem Being Solved

🔀
Fragmented Case Management
Different bureaus maintain separate case records for the same institution — no unified view exists.
⚡
Duplicate Effort
Multiple officers unknowingly work on overlapping complaints about the same institution.
⏰
Missed Deadlines
No centralised SLA tracking means cases get stuck without escalation.
🤝
Coordination Gaps
Bureaus can take conflicting actions on related cases without knowing it.

🚀 Quick Start

Windows — One Click

Double-click run.bat in the project root. It kills old processes, starts both servers, and opens the browser.

Manual Setup (conda)

# 1. Create environment
conda create -n ps2 python=3.12 -y
conda activate ps2

# 2. Install backend
cd backend
pip install -r requirements.txt "pydantic[email]"

# 3. Configure
cp ../.env.example ../.env   # then edit .env

# 4. Migrate + seed
python -m alembic upgrade head
python -m app.db.seed

# 5. Start backend
python -m uvicorn app.main:app --port 8000 --reload
# Frontend (separate terminal)
cd frontend
npm install
npm run dev
# → http://localhost:5173

Docker

docker compose up -d
docker compose exec backend python -m app.db.seed

🤖 Explainable AI Overlap Detection

The system finds potentially related cases across different bureaus using a 3-stage explainable pipeline. Every alert includes human-readable reasons — never a black-box score.

Stage 1
Candidate Discovery
Finds active cases sharing an institution via exact ID → Permanent ID → fuzzy name
→
Stage 2
Triple Scoring
Institution similarity + Lexical text overlap + Semantic cosine similarity
→
Stage 3
Explainability
Plain-English reasons, all scores, detection method, review workflow

Scoring Formula

combined_score = 0.60 × institution_score + 0.40 × text_score

# If semantic matching is enabled:
text_score = 0.40 × lexical_score + 0.60 × semantic_score

# Thresholds (configurable via .env):
institution_name_threshold = 80.0%
complaint_similarity_threshold = 70.0%

Match Reasons (examples)

TriggerHuman-Readable Reason
exact_id"Exact institution match: both cases share the same AICTE Permanent ID."
fuzzy_name"Institution name fuzzy match: similarity 88.5% (threshold 80.0%)."
complaint_text"Complaint text similarity: 76.2% lexical overlap (threshold 70.0%)."
semantic"Semantic similarity: 83.1% via sentence embeddings."

Review Workflow

Authorized officials can: Confirm Related · False Positive · Needs Investigation · Add coordination remarks. The system never auto-merges cases — every decision requires human review.

Enable Semantic AI

# .env
ENABLE_SEMANTIC_MATCHING=true
SEMANTIC_MODEL_NAME=all-MiniLM-L6-v2   # ~90 MB download on first use

⚠️ Cross-Bureau Conflict Prevention

A separate rule-based engine (distinct from overlap detection) identifies coordination issues between bureaus handling the same institution.

RuleTriggers WhenSeverity
multi_bureau_same_issueMultiple bureaus have active cases on the same institution + related categoryHigh
competing_deadlinesRelated cases have deadlines within 7 days of each otherMedium
parallel_escalationOne case is escalated while a related case elsewhere is under processHigh
transfer_conflictA case was transferred while a related case remains active in another bureauMedium
 
POST /api/v1/conflicts/scan          # Run conflict detection
GET  /api/v1/conflicts               # List all warnings
GET  /api/v1/conflicts/{id}          # Warning detail
POST /api/v1/conflicts/{id}/review   # Acknowledge / resolve

☁️ Production Deployment

Azure App Service

# Required environment variables in App Service
DATABASE_URL=postgresql://...@....postgres.database.azure.com/aicte_db?sslmode=require
SECRET_KEY=<64-char random string>
AZURE_STORAGE_CONNECTION_STRING=DefaultEndpointsProtocol=https;...
ENVIRONMENT=production
USE_LOCAL_STORAGE=false

# Post-deploy steps
python -m alembic upgrade head

Key Checklist

✅Change SECRET_KEY to a cryptographically random 64-char string
✅Use PostgreSQL — not SQLite — in production
✅Set USE_LOCAL_STORAGE=false and configure Azure Blob Storage
✅Remove all demo seed data and demo user accounts
✅Terminate TLS at load balancer — never expose FastAPI on port 443
✅Store secrets in Azure Key Vault with Key Vault references
✅Enable automated PostgreSQL backups (7-day minimum retention)
✅Use --workers 1 with gunicorn (APScheduler runs in-process)
